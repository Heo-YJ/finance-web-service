1 프로젝트 목적과 권고안
이 프로젝트는 금융 지식이 부족한 사회초년생이 월급을 받은 뒤 생활비와 비상금, 장기 투자금을
어떻게 나눌지 이해하도록 돕는 교육용 웹 서비스다. 사용자는 실수령액과 필수지출, 현재 비상
금, 투자 성향을 입력하고 3분 안에 계좌별 월 배분안과 3년 세금 비교를 확인한다.

3일 안에 신뢰도 있는 결과를 내기 위해 React와 TypeScript 기반의 단일 페이지 MVP를 권고한
다. 회원가입, 데이터베이스, 실시간 시세, 실제 종목 추천은 제외한다. Spring Boot는 계산 API가
포트폴리오 목적상 꼭 필요한 경우에만 상태 비저장 확장안으로 추가한다.

3 범위 대안 분석

3.1 프론트엔드 중심 MVP

React와 TypeScript에서 입력 검증, 배분 계산, 36개월 시뮬레이션, 세금 비교를 모두 실행한다.
외부 API와 사용자 저장이 없어 배포가 단순하고 계산 로직을 순수 함수로 분리해 테스트하기 쉽
다. 3일 일정에서는 이 구성이 기능 완성도와 설명 가능성을 가장 잘 확보한다.

3.2 상태 비저장 Spring API

React는 화면만 담당하고 Spring Boot의 POST /api/v1/simulations가 계산 결과를 반환한다. 백엔
드 구조와 검증 코드를 보여줄 수 있지만 네트워크 오류 처리와 배포가 추가된다. 프론트엔드 MVP
가 완료된 뒤 시간이 남을 때 적용하는 확장안으로 둔다.

3.3 데이터베이스 포함 풀스택

회원 계정과 결과 이력을 저장하는 구조는 현재 문제에 필요하지 않다. 인증, 개인정보 처리, 스키
마, 마이그레이션이 추가되어 3일 안에 금융 계산과 사용자 설명을 충분히 검증하기 어렵다. 후속
버전에서 사용자 목표 저장이나 반복 방문 검증이 확인될 때 도입한다.

4 권장 MVP와 금융 계산 규칙
결과는 개인 투자 처방이 아니라 공개된 가정에 따른 교육용 시뮬레이션으로 제공한다. 월급 배분
은 실수령액을 기준으로 하고, 연간 총급여는 ISA 유형을 자동 확정하는 값으로 사용하지 않는다.
ISA 유형은 사용자가 금융회사 확인 결과에 따라 선택하며 잘 모르겠음을 허용한다.

4.1 입력과 계산 조건

   •   입력 월 실수령액 월 필수지출 현재 비상금 투자 성향 ISA 유형을 받는다

   •   비상금 목표액은 월 필수지출 3개월분으로 두고 목표까지 남은 금액을 12개월에 나누어
       CMA 월 납입 기준으로 삼는다

   •   ISA 남은 저축 가능액을 배정하되 연 2000만원과 계좌별 실제 잔여 한도를 넘지 않도록
       경고한다

   •   투자 성향 계좌 비율이 아니라 ISA 수익률 시나리오에만 반영하고 실제 종목 추천은 하지
       않는다

5 기술 설계와 3일 일정
   1. 1일 차 금융 규칙과 입력 범위를 확정하고 계산 함수와 단위 테스트를 먼저 구현한다

   2. 2일 차 입력 폼 결과 카드 배분 차트 세금 비교 그래프를 만들고 모바일 화면을 조정한다

   3. 3일 차 경계값과 문구를 검증하고 출처 기준일 면책 문구를 추가한 뒤 배포와 README
       를 마친다

   4. 확장 단계 시간이 남을 때에만 Spring Boot 계산 API를 추가하고 데이터베이스는 사용하
       지 않는다

6 검증과 포트폴리오 활용
일반계좌와 ISA의 세금 차이는 같은 과세 대상 자산과 같은 세전 수익률을 전제로 계산한다. 국내
상장주식 매매차익처럼 일반계좌에서도 비과세인 수익은 15.4퍼센트 과세 대상으로 넣지 않는다.
CMA와 ISA를 일반 적금 하나와 직접 비교하지 않고 비상금 운용과 투자금 절세를 나누어 보여준
다.

포트폴리오에서는 기술 개수보다 규칙의 출처와 기준일, 계산 근거, 예외 처리를 보여주는 것이 중
요하다. README에는 문제 정의, 범위 제외 이유, 계산식, 테스트 사례, 금융 정보 갱신 방법을
기록한다. 이는 금융 서비스에서 요구되는 설명 가능성과 소비자 보호 관점을 드러낸다.

6.1 테스트 기준

월 납입액 0원, 수익률 0퍼센트, 손실 시나리오, ISA 비과세 한도 직전과 직후, 연간 납입한도 초
과, 필수지출이 실수령액보다 큰 경우를 단위 테스트한다 . 모든 금액은 원 단위 정수로 계산하고
화면 표시에서만 반올림한다.

금리와 세율은 assumptions 객체에 값, 상품 유형, 세전 여부, 기준일, 출처 URL을 함께 저장한
다. 화면은 이 정보를 결과 아래에 표시하며 수수료, 해외 원천징수, 상품별 과세 차이를 반영하지
않았다는 제한을 알린다.

6.2 권고안을 바꾸는 조건

로그인 후 결과 저장이 사용자 검증에서 핵심 요구로 확인되거나 실제 상품 비교 API가 필요해지
면 백엔드와 데이터베이스를 도입한다. 반대로 일정이 줄어들면 투자 성향별 수익률 시나리오를
제외하고 기본 배분과 동일 자산 세금 비교만 남긴다.

6.3 개발 순서와 완료 기준

1일 차에는 UI보다 calculateAllocation과 calculateTaxComparison을 먼저 완성해 금융 규칙을 고
정한다.

2일 차에는 계산 결과를 카드와 차트에 연결하고 입력을 바꿀 때 같은 결과가 재현되는지 확인한
다.

3일 차에는 모바일 360픽셀 화면, 키보드 입력, 색 대비, 오류 문구, 출처 링크를 검수하고 배포한
다.

완료 기준은 사용자가 새로고침 후 3분 안에 계산을 끝내고, 각 결과가 어떤 입력과 가정에서 나왔
는지 확인할 수 있으며, 핵심 계산 테스트가 모두 통과하는 상태다.

ISA 세제 혜택은 2026년 9월 확인 기준으로 의무가입기간 3년, 연간 납입한도 2000만원, 일반형
순이익 200만원과 서민형 400만원 비과세, 초과 순이익 9.9퍼센트 분리과세를 적용한다. 납입원
금 범위 내 중도인출이 가능하며 세법과 금융회사 약관 변경 가능성을 전제로 한다.

A 계산 로직

적립식 미래가치는 월 납입액을 매월 말 납입한다고 가정한다. 원금은 월 납입액 곱하기 36으로 계산
한다. 수익은 36개월 후 평가액에서 원금을 뺀 값과 0원 중 큰 값이다. 일반계좌 세금은 과세 대상 수
익의 15.4퍼센트다. ISA 세금은 순수익에서 유형별 비과세 한도를 뺀 초과분의 9.9퍼센트다.

B 핵심 데이터 구조

입 력 모 델 은 monthlyNetIncome, monthlyEssentialExpense, currentEmergencyFund, riskProfile,
isaType 으 로 구 성 한 다 . 가 정 모 델 은 cmaAnnualRate, rateAsOf, sourceUrl, normalTaxRate,
isaTaxRate, isaTaxFreeLimit을 포함한다. 출력 모델은 allocation, emergencyTarget, monthlySeries,
normalAccountTax, isaTax, taxSaving, warnings를 반환한다.

D 서비스 고지 문구

본 서비스는 금융상품 가입이나 투자를 권유하지 않는 교육용 계산기다. 표시 금액은 입력값과 단순화
된 가정에 따른 예상치이며 실제 수익과 세금은 상품, 수수료, 거래 시점, 세법, 금융회사 약관에 따라
달라질 수 있다. CMA 유형에 따라 예금자보호 대상이 아닐 수 있고 투자상품은 원금 손실이 발생할 수
있다.
